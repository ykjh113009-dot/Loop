# Project audit (November 2026)

What was found when the whole project was inspected before Phase 1, and what was done about it.

## What exists and works

| Area | State |
| --- | --- |
| Framework | Next.js 16 App Router, TypeScript, Tailwind v4. Lint, type check and production build are clean. |
| Sign-in | Google sign-in through Supabase. The database refuses any email outside the school domain. |
| Database | 43 tables, all with Row Level Security, 94 rules. Every table carries `school_id`. |
| Features already built | Home dashboard, clubs and club posts, events and RSVPs, direct and club chats, notifications, reports and moderation, announcements, points and badges, weekly challenges, polls, volunteering hours, tutors and study buddies, marketplace, Tawjihi Q&A, student council and elections, suggestion box, counselor channel, admin overview. |
| Storage | One private bucket `post-images` (1 MB limit, images only). |
| Hosting | Vercel project `loop-demo-login`, linked to GitHub. Previews are protected, production is public. |

## Problems found

| # | Problem | Severity | Status |
| --- | --- | --- | --- |
| 1 | The live site ran on the **demo** database (48 fake students sharing one password), not on the `loop-school` project named as production. `loop-school` was paused and empty. | High | Owner chose `loop-school`. Waiting for a free project slot (see `deployment.md`). |
| 2 | `main` was 6 commits behind the code that was live. | Medium | Fixed: `main` now holds everything. |
| 3 | Only three roles (student, moderator, admin). No Super Admin, no owner, admins could promote anyone to admin. | High | Fixed in Phase 1. |
| 4 | Moderators could suspend students, and admins could suspend "until lifted" (a permanent ban). | Medium | Fixed: admins only, 1 to 365 days. |
| 5 | Admins could act on other admins (suspend, remove, demote). | High | Fixed: only on accounts below their own role. |
| 6 | No two-step sign-in for admins. | High | Fixed: authenticator app, enforced in the database. |
| 7 | No rate limits anywhere: a script could post or message without limit. | High | Fixed for posts, messages, clubs, events, listings, reports, suggestions, questions and answers. |
| 8 | The activity log could be rewritten by database functions. | Medium | Fixed: a trigger refuses edits and deletes. |
| 9 | No record of sign-ins or new devices. | Medium | Fixed: `security_events`, with an alert on a new browser. |
| 10 | Any admin could change school settings (name, grades, sign-up rule). | Medium | Fixed: Super Admins only. |
| 11 | Supabase Free plan: **no automatic backups**, and a project **pauses after about a week without traffic**. | High | Needs an owner decision (see `backup-and-recovery.md`). |
| 12 | Push notifications are not configured on Vercel (no `SUPABASE_SECRET_KEY`, VAPID keys or `CRON_SECRET`). In-app notifications work. | Low | Open. |
| 13 | The old Vercel project `loop` has a broken Git link to the old repository name. | Low | Left alone; `loop-demo-login` replaces it. |
| 14 | Supabase "leaked password protection" is off. | Low | Not relevant: real accounts have no Loop password (Google only). |
| 15 | No Arabic or right-to-left support yet. | Planned | Phase 2 (with settings and the language switcher). |

## Missing features (by phase)

Phase 2: profile extras (cover photo, skills, portfolio), settings, follows and friend requests, a school-wide feed with reactions, comments, saves, stories, message requests and group chats, notification preferences, Arabic.
Phase 3: student groups, club tools, houses, rewards shop, Leadership Dashboard.
Phase 4: event proposals, capacity and waitlists, event volunteers, event chats.
Phase 5: Academy, opportunities, skill exchange, school map, Passport, magazine, photo competitions.
